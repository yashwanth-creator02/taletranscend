# TaleTranscend — File Inventory

One-line duty for every file tracked by git in this repository, grouped by area and ordered like the repository tree. Use it to find where a behavior lives, what a file is for, or who consumes it — without opening files one by one.

- **Source of truth:** `git ls-files` — 346 tracked files as of 2026-10-18 (this file included).
- **Maintenance:** when a tracked file is added, renamed, moved, or deleted, update its entry here in the same change (`AGENTS.md` principle 7; `CONTRIBUTING.md`). A stale entry is worse than no entry.
- **Format:** one `path` — duty line per file.

## Repository Root

- `.editorconfig` — EditorConfig root settings: UTF-8, LF endings, 2-space indent, final newline; Markdown is exempt from trailing-whitespace trimming.
- `.env.example` — Template for a local `.env`: Vite Firebase keys (`VITE_FIREBASE_*`), `VITE_APP_ID`, `VITE_DEV_MODE`, and the dynamic-artifacts flag.
- `.firebaserc` — Firebase CLI config pinning the default project alias to `taletranscend`.
- `.gitignore` — Repository ignore rules: env/credentials, `node_modules`, build and test output, local scripts and generated assets, tool-specific state, and the brand-managed `agents/skills/` folder.
- `.prettierignore` — Prettier exclusions: `.gitignore`, `README.md`, minified files, `package-lock.json`, `node_modules`, `dist`, `functions/lib`.
- `.prettierrc` — Prettier options: 2-space indent, semicolons, single quotes, ES5 trailing commas, 100-char width, LF endings.
- `eslint.config.js` — Flat ESLint config: recommended JS rules, Prettier compatibility, browser/node globals, underscore-prefixed unused vars allowed.
- `firebase.json` — Firebase config: Firestore database/rules/indexes, emulator ports, Hosting rewrites for the MPA, security and cache headers.
- `opencode.json` — OpenCode config registering the chrome-devtools, firebase, and vercel MCP servers for project sessions.
- `package-lock.json` — npm lockfile pinning the root package's full dependency tree; regenerated by `npm ci`.
- `package.json` — Root manifest: scripts (dev, build, verify, test:rules, e2e), dependencies, lint-staged hook config, Node >=20 engine.
- `playwright.config.js` — Playwright config: `e2e/` specs in chromium and firefox against this worktree's allocated dev port (read from `.dev-port`, defaulting to 5173) with an auto-started Vite dev server.
- `skills-lock.json` — Lockfile recording source, path and hash for agent skills fetched from `firebase/agent-skills`.
- `tsconfig.json` — TypeScript config for `src/`: ESNext with bundler resolution, `@`-prefixed path aliases, noEmit and strict; used by `npm run type-check`.
- `vercel.json` — Vercel deployment config: `vite build` to `dist`, hierarchical URL rewrites mirroring Firebase, security and cache headers.
- `vite.config.js` — Vite MPA config: `src/views` root with 11 HTML entries, dev-server route rewrites, aliases, chunk splitting, PWA plugin. Dev-server port comes from `.dev-port` when allocated for the worktree, otherwise Vite's default.
- `vitest.config.js` — Vitest config for `src/` unit tests (jsdom, setup file, coverage) re-declaring the project path aliases.
- `vitest.rules.config.js` — Minimal Vitest config selecting `firestore/tests/*.test.ts` in a node environment; consumed by `npm run test:rules`.

## Cloud Functions (`functions/`)

- `functions/.gitignore` — Ignores node_modules, compiled lib/, logs and env files in functions/ while keeping .env.example tracked.
- `functions/README.md` — Documents the four Cloud Functions, the BYOK AI decision, admin bootstrap, local dev, and that none are deployed on the Spark plan.
- `functions/package-lock.json` — Lockfile pinning the functions package's dependency tree (firebase-admin, firebase-functions, TypeScript).
- `functions/package.json` — Functions manifest: tsc build plus emulator/shell/deploy scripts, firebase-admin and firebase-functions deps, Node 20 engine.
- `functions/src/admin/setModeratorClaim.ts` — Callable function letting an existing admin grant or revoke the moderator custom claim that the rules' isAdmin() reads.
- `functions/src/index.ts` — Cloud Functions entry point: initializes firebase-admin and re-exports the two triggers, the moderator callable, and the sitemap function.
- `functions/src/sitemap.ts` — onRequest HTTP function serving a dynamic sitemap.xml built from published tales and chapter counts, with caching headers.
- `functions/src/triggers/onCommentWrite.ts` — Firestore trigger incrementing or decrementing tales/{taleId}.commentCount when comment docs are created or deleted.
- `functions/src/triggers/onReactionWrite.ts` — Firestore trigger incrementing or decrementing tales/{taleId}.reactionCount when reaction docs are created or deleted.
- `functions/tsconfig.json` — Functions TypeScript config: ES2022/NodeNext, strict, compiling src/ into lib/ with source maps (excludes node_modules, lib).

## Firestore Security and Data

- `firestore.rules` - Security rules for the v1/taletranscend/projects/v1 tree: per-collection ownership checks, field validation, and a deny-all fallback. Notification updates are allowlisted to `isRead`, `readAt`, and `isPinned` for the owner.
- `firestore.indexes.json` — Composite index definitions for tales, comments, drafts, and bookmarks queries; deployed via `firebase deploy --only firestore:indexes`.
- `firestore/tests/rules.emulator.test.ts` - Emulator-backed Vitest suite asserting `firestore.rules` decisions for reactions, reader progress, followers, inquiries, notification pin/read allowlisting, and fallback paths.

## Scripts and Verification

- `scripts/generate-sitemap.js` — Writes public/sitemap.xml for core routes plus a hardcoded list of known tales and chapters; run by npm run build.
- `scripts/lint-tokens.mjs` — Fails the build when raw hex/rgba/hsl colour literals appear in src CSS outside tokens.css and reader-themes.css.
- `scripts/seed-tales.mjs` — One-off seeder signing in anonymously and upserting 24 sample folklore tales with chapters into Firestore; npm run seed:tales.
- `execution/run_verify.py` — Deterministic verification runner executing format check, token lint, ESLint, type-check and unit tests, aborting on first failure.
- `execution/verify_author_flows.py` — Runner of token lint, type-check and targeted Vitest suites for author service, inquire, publish, profile-sync and validation.
- `execution/verify_interactions_and_profile.py` — Runner of token lint, type-check and Vitest suites for navigation/bfcache, tale hero interactions, profile UI, downloads and AI service.
- `execution/verify_navigation_and_ui.py` — Runner enforcing index-only footer and brand-asset checks, then token lint, type-check and navigation/nav/toast/toc suites.
- `execution/setup_worktree.py` — Mandatory new-worktree bootstrap: installs dependencies, copies gitignored `.agents/skills/`, `.vercel/project.json`, `.env` and `.env.local` from the primary checkout (refusing any destination git would track), warms the firebase-tools module graph and retries MCP verification to fit the fixed 30s startup budget, allocates a per-worktree dev port, then reports MCP state; supports `--check`, `--source`, `--list-ports` and `--release-port`.

## End-to-End Tests

- `e2e/specs/library.spec.js` - Playwright spec for library.html covering tale-card loading, search filtering, and pagination.
- `e2e/specs/nav-brand-menu.spec.js` — Playwright spec for the brand block: guest mark as home link, wordmark navigation, member account-menu trigger with hover hamburger glyph, brand-anchored dropdown geometry plus Escape/outside-click closing, avatar profile link, and mobile fit. Blocks Firebase network and drives `updateNavUser()` from the page for deterministic state; run with `--workers=1`.
- `e2e/specs/nav-notifications.spec.js` — Playwright spec for the floating notification trigger: body-level mounting outside the header, hidden start state, unread badge and geometry below the nav bar, pinned-only visibility, `body:has()` toast-column shift, drawer anchoring with Escape/outside-click closing, and mobile fit. Blocks Firebase network and drives the page's own notification module for deterministic state; run with `--workers=1`.
